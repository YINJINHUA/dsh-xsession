# DSH 同项目对话通信

[English](README.en.md)

让同一工作区、同一 DSH 宿主内的对话互相发信。可与 **codex-dsh-project-bridge** 配套：前者连接 Codex 与 DSH，本插件连接 DSH 内的协调、执行和审查对话。

**版本：0.1.1，正式发布目标为 npm `latest`。** 宿主接口以 DSH Desktop 0.2.0-rc.2 为基准；验证范围见[测试说明](docs/VALIDATION.md)。

## 适合谁

面向重视最小权限、希望 DSH 执行／审查对话保持“工作区内修改”或“只读”的用户。对话可直接使用本插件工具通信，无需为了发信改成完全访问权限，也无需从低权限对话启动外部 CLI。只读会话可以发信，但仍不能写项目文件。

本插件不会修改会话权限，也不额外建立安全沙箱。它允许同工作区不同权限等级的对话互发消息；低权限发来的文本仍可能影响高权限接收者，因此收件方必须独立核对授权。建议执行者和审查者保持最低必要权限，只把确有必要的操作交给协调者。

## 安装

在 DSH 桌面客户端「添加插件」填入 `dsh-xsession`（指定版本可填 `dsh-xsession@0.1.1`），不需要输入 `npm install` 命令。此方式需该版本已在 npm 发布；如果尚未发布，请使用维护者提供的 `.tgz`。也可以从 GitHub Release 下载 `.tgz`，将文件路径交给插件管理器安装。

用 DSH 内的插件开关启用／停用；不需要启动脚本、端口配置或全局安装。更新已安装的包时，按客户端提示重启。卸载使用插件管理器，不手动删除正在使用的目录。

## 能做什么

| 工具 | 用途 |
| --- | --- |
| `xsession_list` | 列出同工作区顶层对话及在线状态；默认不读取历史标题 |
| `xsession_send` | 按对话 ID 发信；提供稳定的 `requestId` 防止同一请求重复投递 |
| `xsession_inbox` | 查看自己的近期消息及回执 |

闲置对话默认被唤醒；正在工作的对话默认仅注入上下文，不强行中断。`accepted` 只表示宿主入队调用成功，**不表示对方已读取或完成**。`outcome_unknown` 不应换编号重发。

支持 `workspace-write` 和 `read-only` 会话发消息，不会改权限。唤醒可能消耗模型额度。对话消息是代理提供的数据，不是用户新授权；高权限对话仍须自行检查任务范围。

## 配套示例

1. Codex 对话 1 把详细计划写入项目文档，由 Codex 对话 2 通过跨应用桥联系 DSH 对话 3。
2. DSH 对话 3 使用本插件联系已经创建并打开的执行对话 4；消息只写任务摘要、文档路径和验收要求。
3. 对话 4 在项目内生成报告，再用本插件向 3 回信；3 通过跨应用桥交给 2，再交给 1。
4. 对话 1 给出审查说明，沿 2 → 3 交给独立审查对话 5，结果沿原路返回。

**本插件不创建对话。** 可由 DSH 正常新建，或使用跨应用桥现有创建能力。用后者创建 4/5 时显式选 `--dsh-permission inherit`，并确认软件默认权限；不要把协调对话的完全权限误当成执行对话的必要权限。[完整边界与参数](docs/PROTOCOL.md)。

## 限制

- 仅同一规范化工作区根目录；父子目录不视为同一个工作区。离线、已归档及真正的子代理不可投递，普通分叉对话可用。
- 不恢复会话、不广播、不提供共享黑板；长内容直接用项目文档交接。当前没有跨进程或跨机器路由。
- 正文最多 4,000 个 UTF-16 码元。自动防重与限流是防误操作措施，不能阻止恶意代理绕开协作约定。
- 每个插件实例最多保留 2,000 条回执，容量满后拒绝新发送，已有请求仍可查询；先核对未决任务再受控重载，不能靠盲目重发恢复。
- 收件索引和幂等回执仅在插件本次运行期间保留。重启后不得盲目重试未知投递；先查看目标会话。宿主自身如何持久化历史取决于其配置。
